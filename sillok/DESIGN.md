# 조선왕조실록 일진(일간지) 전수 추출 & 60간지 통계 검정 — 설계서

> 이 문서는 파이프라인의 설계 근거(리서치로 확인된 사실), 파싱 구조, 검증 산술,
> 통계 방법, 3계층 작전 계획을 담은 아티팩트다. 실행 코드는 `sillok_pipeline/`,
> 사용법은 `README.md` 참조.

## TL;DR

- **크롤링하지 마라. 벌크 XML을 받아라.** 국사편찬위원회 실록 원문 전체는
  공공데이터포털(dataset 15053647, "이용허락범위 제한 없음")에 UTF-8 XML로 공개돼
  있고, 사이트 robots.txt는 역사적으로 `User-agent: * / Disallow: /` 전면 차단이었으며
  `/id/` 기사 페이지는 실제로 자동접근이 차단된다. 벌크 파일에는 각 기사 날짜에
  `<dateOccured type="간지">`로 일간지가 이미 태그돼 있어 파싱이 크롤링보다 빠르고
  합법적이며 정확하다.
- **간지는 원본에 명시돼 있으므로 "추출"이 본질이고, JDN 산술 + korean_lunar_calendar로
  "검증"만 하면 된다.** 음력 날짜(왕대·연·월·일·윤달)를 양력으로 변환해 (JDN) mod 60으로
  계산한 일간지가 원문 태그와 일치하는지 교차검증하는 게이트를 반드시 통과시킨 기사만
  통계에 넣는다.
- **통계는 사건유형별로 60간지/천간10/지지12 관측분포를 균등분포와 카이제곱 적합도 검정**
  하고, 여러 사건유형·세 층위를 동시에 검정하므로 Bonferroni 보정을 적용하며, 기대도수
  5 미만 셀이 많은 60간지 검정은 검정력이 낮으니 천간/지지 층위를 1차 결론으로 삼는다.

## Key Findings (리서치로 확인된 사실)

### 데이터 소스

- 공공데이터포털 **dataset 15053647** "교육부 국사편찬위원회_조선왕조실록 정보_실록원문_20221103":
  확장자 XML, 무료, **이용허락범위 제한 없음**, UTF-8 인코딩. 등록 2022-11-03, 수정 2025-06-02.
- 실록 규모: 태조부터 철종에 이르는 25대 국왕의 실록 28종, 1392~1863년 472년, 편년체,
  전체 1,893권 888책. 총 글자수 약 4,965만 자(49,646,667자). — **개별 기사 총건수(≈40만)
  정확 출처는 미확인이므로 파이프라인 종료 시 실측값으로 대체할 것.**
- 고종·순종실록은 **별도 dataset 15053646**, 인물 부가정보는 CSV **dataset 15053645**.
- 스키마: 한국사데이터베이스 DTD Last Updated 2015.11.30 ver 1.3 (`history.dtd`).
- 파일명 규칙: `2nd_` 접두 + 3글자 왕대코드(w?a) + `_` + 번호. 예 `2nd_waa_000.xml`(태조 총서),
  `2nd_waa_101.xml`(태조 재위 1년), `2nd_wda_132.xml`(세종 32년), 부록은 `_200`/`_300`/`_400`.
  배포는 단일 ZIP.
- 웹서비스 기사 ID 체계(크롤링 시): `k?a_YYYYMMDD_NNN` 형식. 예 `kaa_10201006_001` =
  태조실록 2년 1월 6일 첫 기사. 앞 3글자 = 왕대코드. 웹 ID와 벌크 XML의 id는 접두만
  다르다(k?a vs 2nd_w?a). 월 뒤 1자리는 윤달 여부(0/1).
- 웹서비스 목록 저장은 한 번에 최대 5,000건, `^` 구분자 텍스트.

### robots.txt / 법적

- 실록 사이트는 `user-agent:* disallow:/` 전면 차단 이력. `/id/` 기사 페이지 자동 fetch는
  "Site disallows automated access"로 차단됨을 실측.
- 이용약관 위반 크롤링은 민·형사 리스크. 공공데이터포털 벌크 데이터는 "제한 없음"이므로 안전.

### 파싱 구조 (history.dtd)

- 계층: `<level1>`(왕대) → `<level2>`(재위년) → `<level3>`(월) → `<level4>`(일) →
  `<level5>`(기사) → `<level6>`.
- 날짜: `<level4>/<front>/<biblioData>/<date>/<dateOccured>` 여러 개, `type` 속성으로
  서기/간지/재위연도/개국연호/중국연호/단기/일본연호/display 구분.
  **`<dateOccured type="간지">壬子</dateOccured>`가 일간지.** 서기 `date="1393-01-06L0"`
  형식에서 L 뒤 0/1이 평/윤달.
- 제목: `<level5>/<front>/<biblioData>/<title>/<mainTitle>`.
- 본문: `<level5>/<text>/<content>/<paragraph>`.
- 주의: `<level2>`,`<level3>`,`<level4>`에도 `간지` 속성이 있으나 **연주(年)·월주(月)·일진(日)이
  다르다.** 우리가 필요한 건 `<level4>`(일 단위)의 간지 = 일진.

### 검증 산술 & 라이브러리

- **korean_lunar_calendar** (PyPI 0.3.1, KARI 기준, 네트워크 불필요): 음력 변환 1000-01-01 ~
  2050-11-18, 양력 변환 1000-02-13 ~ 2050-12-31 지원 → 실록 전 구간 1392~1863 커버.
  API: `setLunarDate(y,m,d,intercalation)` → `SolarIsoFormat()`,
  `getChineseGapJaString()`(일주 간지 포함).
- **JDN 산술**: 그레고리력 JDN 계산 후 일간지 = (JDN + k) mod 60. 앵커: **1900-01-01(양력)=갑술(甲戌)일**.
  근거: 1901-01-01=기묘(己卯), 1902-01-01=갑신(甲申)에서 역산 일치. 런타임에 재확인
  (`verify.selfcheck_anchor` — 산술 + korean_lunar_calendar 독립 교차검증).

### 사건유형 키워드 (실록 정형표현)

- **붕어/승하**: 훙(薨)·훙서(薨逝)·승하(昇遐)·붕(崩)·붕어(崩御)·예척(禮陟).
- **졸기(신하 사망)**: 졸(卒)·"졸하다"·"졸기".
- **처형/사사**: 복주(伏誅)·사사(賜死)·참(斬)·효수(梟首)·환열(轘裂)·주(誅)·능지처사·처참.
- **재변(천재)**: 일식·월식·지진·지동·혜성·객성·성변(星變)·뇌진(雷震)·벼락.
- **즉위**: 즉위(卽位)·선위(禪位)·내선(內禪)·수선(受禪).
- **반정/정변**: 반정(反正)·모반(謀反)·정난(靖難)·폐위(廢位).

## 검증 게이트 정책

`verified==1`(JDN·라이브러리·원문 3자 일치)만 통계 대상. `verified==0`은 로그로 남겨
수기 검토(윤달 표기 불일치, 실록 자체 간지 오기 가능성). **실록의 재위년→서기 음력연 환산은
칭원법이 왕대별로 달라 오류가 잦으므로**, 가능하면 `<dateOccured type="서기">`의 `date`
속성을 음력 연·월·일로 직접 사용하는 것이 가장 안전하다(`run.run_verify`가 그렇게 함).

## 통계 방법 & 해석 지침

- 사건유형별로 천간(df=9)·지지(df=11)·60간지(df=59) 관측도수를 균등기대와 `scipy.stats.chisquare`.
- Bonferroni 분모 = 사건유형수×층위수(예 6×3=18), α'≈0.05/18≈0.0028.
- **60간지 층위**: 사건유형당 표본이 수백 이하면 셀당 기대도수<5 → 카이제곱 근사 부정확
  (`LOW_POWER` 플래그). 이 경우 몬테카를로 재표집 p값 또는 천간/지지 층위 결론을 우선.
- **혼재변수 주의**: 기록밀도가 왕대·계절별로 불균등하고, 즉위·붕어는 소수 사건이라 검정력
  태생적 한계. **붕어처럼 N이 왕 수(≈25~28) 수준으로 극소하면 검정 자체가 무의미** →
  기술통계·사례표만 제시.

## 3계층 작전 계획 (병렬 실행)

- **소대장(오케스트레이터)**: 전체 파이프라인 소유. `progress/manifest.json`,
  `progress/schema_probe.json` 생성. 벌크 ZIP 다운로드·해제 후 왕대 구간 할당.
- **분대장 ×2**: (1) 파싱/분류 — 왕대 구간 분배, SQLite 병합, 기사수 대조.
  (2) 검증/통계 — 검증 게이트 실행, `verified=0` 로그 리뷰, 통계·리포트.
- **분대원 ×N**: 왕대 1~수개씩 할당. `parse_bulk_xml`+`classify` 후 `out/<code>.db`와
  `.done` 마커 생성. 왕대별 파티션이 자연 샤딩(락 불필요).
- **작업 순서 게이트**: ①프로브 완료 → ②전 왕대 파싱 완료(총수 실측) →
  ③검증 통과율 리포트(>98% 기대) → ④통계. 각 게이트를 별도 커밋/마커로 분리해 재시작 안전.

## Recommendations

1. **1단계**: 15053647+15053646 ZIP 다운로드 → `probe`로 level4 id 자리수·간지 태그 위치·
   앵커·KING_CODES 확정 → 코드의 "추측" 교정. **이 게이트 통과 전 통계 금지.**
2. **2단계**: 전수 파싱 → 검증 통과율 측정. **<98%면** id 자리수/윤달 파싱 버그 의심,
   프로브 재실행. 검증엔 `<dateOccured type="서기">` 속성 직접 사용 권장.
3. **3단계**: 천간·지지 층위부터 검정. **어떤 사건유형이든 N<50이면** 60간지 검정 생략,
   기술통계+지지 층위만 보고.
4. **4단계**: Bonferroni 통과 신호가 있으면 왕대별 층화 재검정으로 기록편향 배제.
   붕어/즉위처럼 N≈수십은 처음부터 검정 제외, 사례표만.

## Caveats

- **robots.txt 현재값 미확인**: 전면차단 이력 + `/id/` 자동접근 차단 실측만. 벌크 경로라 무영향.
- **왕대코드 매핑·id 자리수·DOM 셀렉터는 추측 포함**: 반드시 런타임 프로브로 확정.
- **간지 층위 구분**: `<level4>` 간지=일진만 사용. 연/월주 혼입 금지.
- **korean_lunar_calendar 범위**: 음력 1000년부터 → 태조 원년(1392) 이후 전 구간 OK.
- **기사 총건수(≈40만)는 미확인 추정치** — 파싱 종료 시 실측값으로 대체. 검증 가능한 규모
  지표는 "1,893권 888책, 약 4,965만 자".
- **통계적 한계**: 일진은 60일 주기 순환이라 장기간 다수 사건은 자연히 균등에 수렴.
  유의한 편차는 인과가 아니라 기록·편찬 관행(의례 집중, 재이 관측 보고 관행) 혼재변수를 먼저 의심.
- **실록 자체 간지 오기**: 드물게 원문 간지가 산술과 불일치. `verified=0` 표본은 버리지 말고
  별도 집계해 데이터 품질 지표로 활용.
