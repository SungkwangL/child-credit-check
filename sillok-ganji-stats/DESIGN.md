# 설계서 (아티팩트) — 조선왕조실록 일진 추출 & 60간지 검정

> 파이프라인의 설계 근거(리서치로 확인된 사실), 파싱 구조, 검증 산술, 통계 방법,
> 3계층 작전 계획. 실행 코드는 `src/sillok_pipeline.py`, 사용법은 `README.md`.

## TL;DR

- **크롤링하지 마라. 벌크 XML을 받아라.** 실록 원문 전체는 공공데이터포털(dataset 15053647,
  "이용허락범위 제한 없음")에 UTF-8 XML로 공개돼 있고, `sillok.history.go.kr` robots.txt는
  역사적으로 전면 차단이었으며 `/id/` 기사 페이지는 자동접근이 차단된다. 벌크 파일에는 각
  기사 날짜에 `<dateOccured type="간지">`로 일간지가 이미 태그돼 있다.
- **간지는 원본에 명시돼 있으므로 "추출"이 본질이고, JDN 산술 + korean_lunar_calendar로
  "검증"만 하면 된다.** 음력 날짜를 양력으로 변환해 (JDN) mod 60으로 계산한 일간지가 원문
  태그와 일치하는 기사만 통계에 넣는다.
- **통계는 사건유형별 60간지/천간10/지지12 관측분포를 균등분포와 카이제곱 적합도 검정**하고,
  다중검정이므로 Bonferroni 보정하며, 기대도수 5 미만 셀이 많은 60간지는 검정력이 낮으니
  천간/지지 층위를 1차 결론으로 삼는다.

## Key Findings

### 데이터 소스
- dataset **15053647** "국사편찬위원회 조선왕조실록 원문": XML, 무료, 이용허락범위 제한 없음,
  UTF-8. 등록 2022-11-03, 수정 2025-06-02.
- 규모: 태조~철종 25대 28종, 1392~1863년, 편년체, 1,893권 888책, 약 4,965만 자.
  개별 기사 총건수(≈40만)는 미확인 추정치 → 파싱 종료 시 실측값으로 대체.
- 고종·순종은 별도 dataset 15053646, 인물 CSV는 15053645.
- 스키마: 한국사DB DTD ver 1.3 (`history.dtd`).
- 파일명: `2nd_` + 3글자 왕대코드(w?a) + `_` + 번호. 예 `2nd_waa_000`(태조 총서),
  `2nd_waa_101`(태조 1년), `2nd_wda_132`(세종 32년), 부록 `_200/_300/_400`.
- 웹 기사 ID: `k?a_YYYYMMDD_NNN`. 예 `kaa_10201006_001` = 태조 2년 1월 6일 첫 기사.
  월 뒤 1자리는 윤달 여부. 벌크 id와 접두만 다름(k?a vs 2nd_w?a).

### robots.txt / 법적
- 실록 사이트 `user-agent:* disallow:/` 전면차단 이력, `/id/` 자동접근 차단 실측.
- 약관 위반 크롤링은 민·형사 리스크. 공공데이터포털 벌크는 "제한 없음"이라 안전.

### 파싱 구조 (history.dtd)
- 계층: level1(왕대) > level2(재위년) > level3(월) > level4(일) > level5(기사) > level6.
- 날짜: `level4/front/biblioData/date/dateOccured`, `type`으로 서기/간지/재위연도/… 구분.
  **`<dateOccured type="간지">`가 일진.** 서기 `date="1393-01-06L0"`의 L 뒤 0/1이 평/윤달.
- 제목: `level5/.../mainTitle`. 본문: `level5/text/content/paragraph`.
- **주의**: level2/level3/level4에 모두 간지 속성이 있으나 연주·월주·일진이 다르다.
  필요한 건 level4(일)의 간지 = 일진.

### 검증 산술 & 라이브러리
- **korean_lunar_calendar** 0.3.1 (KARI 기준, 네트워크 불필요): 음력 1000-01-01 ~ 2050 지원
  → 실록 전 구간 커버. `setLunarDate` → `SolarIsoFormat()`, `getChineseGapJaString()`(일주 포함).
- **JDN 앵커**: 1900-01-01(양력)=甲戌. 1901-01-01=己卯, 1902-01-01=甲申과 일치.
  런타임 `selfcheck_anchor`가 산술 + 라이브러리 독립 교차검증.

### 사건유형 키워드
- 붕어/승하: 훙(薨)·승하(昇遐)·붕(崩)·예척(禮陟). 졸기: 졸(卒).
- 처형/사사: 복주(伏誅)·사사(賜死)·참(斬)·효수(梟首)·환열(轘裂)·능지처사.
- 재변: 일식·월식·지진·지동·혜성·객성·성변·뇌진·벼락.
- 즉위: 즉위(卽位)·선위(禪位)·내선·수선. 반정: 반정(反正)·모반·정난·폐위.

## 검증 게이트 정책
`verified==1`(JDN·라이브러리·원문 3자 일치)만 통계 대상. `verified==0`은 로그로 남겨 수기 검토
(윤달 표기 불일치, 원문 간지 오기 가능성). 재위년→서기 음력연 환산은 칭원법이 왕대별로 달라
오류가 잦으므로 `<dateOccured type="서기">`의 date 속성을 음력 연·월·일로 직접 사용한다.

## 통계 방법 & 해석
- 천간(df=9)·지지(df=11)·60간지(df=59)를 균등기대와 `scipy.stats.chisquare`.
- Bonferroni 분모 = 사건유형수×층위수(예 6×3=18), α'≈0.0028.
- 60간지는 셀당 기대도수<5면 `LOW_POWER`(근사 부정확) → 천간/지지 우선 또는 몬테카를로 p값.
- **혼재변수**: 기록밀도 불균등, 즉위·붕어는 소수. N이 왕 수(≈25~28)면 검정 무의미 → 사례표만.

## 3계층 작전 계획 (병렬)
- **소대장(오케스트레이터)**: 파이프라인 소유, `progress/manifest.json`·`schema_probe.json` 생성,
  ZIP 다운로드·해제 후 왕대 구간 할당.
- **분대장 ×2**: (1) 파싱/분류 — 왕대 분배, SQLite 병합, 기사수 대조. (2) 검증/통계 — 게이트 실행,
  verified=0 리뷰, 통계·리포트.
- **분대원 ×N**: 왕대별 파티션(자연 샤딩), `out/<code>.db` + `.done` 마커.
- **게이트 순서**: ①프로브 → ②전 왕대 파싱(총수 실측) → ③검증 통과율(>98%) → ④통계.
  각 게이트를 별도 커밋/마커로 분리해 재시작 안전.

## Caveats
- robots.txt 현재값 미확인(벌크 경로라 무영향). 왕대코드·id 자리수·DOM 셀렉터는 추측 포함 →
  반드시 probe로 확정. level4 간지=일진만 사용(연/월주 혼입 금지).
- korean_lunar_calendar 음력 1000년부터 → 태조 원년 이후 전 구간 OK.
- 기사 총건수(≈40만)는 추정 → 파싱 종료 시 실측 대체. 규모 지표는 "1,893권 888책, 약 4,965만 자".
- 일진은 60일 주기 순환이라 대량 사건은 자연히 균등 수렴. 유의 편차는 인과 아닌 기록·편찬 관행
  혼재변수를 먼저 의심. 원문 간지 오기(verified=0)는 버리지 말고 데이터 품질 지표로 별도 집계.
